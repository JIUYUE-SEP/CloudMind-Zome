# CloudMind-Zome 开发指南

> 版本：1.0 | 日期：2026-06-22
> 面向开发者的快速上手和调试指南。

---

## 1. 环境准备

### 1.1 要求与技术栈

**运行要求**：
- Node.js 22+
- Rust 1.80+
- protoc

**技术栈**：
- 后端：Node.js 22 + Fastify 5
- 前端：Nuxt 3 + Vue 3 + Pinia + TypeScript
- 桌面：Tauri 2（Rust + WebView2）
- 侧车：Rust `crates/zome-sidecar`（gRPC）
- 包管理：pnpm workspace + Turborepo

### 1.2 安装依赖

```bash
pnpm install
```

### 1.3 启动开发环境

```bash
# Web 模式（同时启动 engine + web）
pnpm dev

# Tauri 桌面模式（需 Rust）
pnpm --filter @mindcloud/desktop dev
```

服务启动后：
- 前端：`http://localhost:1420`
- 后端 API：`http://127.0.0.1:8848`
- WebSocket：`ws://127.0.0.1:8848/api/v1/ws`

### 1.4 环境变量

| 变量 | 说明 | 默认值 |
|------|------|--------|
| `CLOUDMIND_DATA_DIR` | 运行时数据目录（配置、Agent 数据、日志） | `~/.cloudmind-zome` |
| `CLOUDMIND_MASTER_KEY` | 用于加密 API Key 的主密钥；若未设置则自动生成 `.master-key` | 自动生成 |
| `CLOUDMIND_ALLOWED_ORIGINS` | CORS 允许来源，多个用英文逗号分隔 | `http://localhost:3000,http://127.0.0.1:3000,http://localhost:1420` |
| `LOG_LEVEL` | 日志级别 | `info` |
| `NODE_ENV` | 运行环境；设为 `e2e` 时 CORS 放行所有来源 | — |

## 3. 启动流程详解

```
pnpm dev
  │
  ├── turborepo 并行/串行调度
  │
  ├── services/engine/src/bootstrap.ts
  │   ├── 创建 ApiContext（per-Agent repository 工厂）
  │   ├── 注册 Fastify 路由（agents / chat / memory / actions / skills / ws）
  │   └── 启动 HTTP + WebSocket 服务
  │
  └── apps/web
      └── nuxt dev → http://localhost:1420
```

桌面模式：

```
apps/desktop/src-tauri/src/main.rs
  │
  ├── 启动 Rust sidecar（zome-sidecar）
  │   └── gRPC 服务（向量搜索、token 计数、AES 加密）
  │
  ├── sidecar 启动 Node engine
  │
  └── WebView2 加载 Nuxt 前端
```

## 4. 调试技巧

### 4.1 查看 Agent 日志

AgentWorker 的日志包含完整的启动和 Job 执行信息。设置 `LOG_LEVEL=debug` 可查看详细日志。

关键日志标记：
- `[startup]` — 启动阶段耗时
- `AgentWorker started for {name}` — Worker 启动成功
- `ReAct loop finished` — ReAct 循环结束
- `Job execution failed` — Job 执行异常

### 4.2 查看 WebSocket 流量

浏览器 DevTools → Network → WS → 选择 `ws://127.0.0.1:8848/api/v1/ws`

常见帧类型：
- `chat.send` → `chat.message` / `chat.thinking` / `chat.tool_call`
- `agent.stop` → `agent.status` (idle)

### 4.3 检查 per-Agent 存储

```bash
ls ~/.cloudmind-zome/agents
# 每个 Agent 对应一个目录，内含 agent.json、messages.jsonl、memories.jsonl 等
```

## 5. 常见开发任务

### 5.1 添加新工具

1. 在 `services/engine/src/tools/builtin/` 下创建新文件
2. 实现 `Tool` 对象（定义名称、描述、Zod schema、execute 函数）
3. 在 `services/engine/src/tools/builtin/index.ts` 导出并在启动时注册到 `ToolRegistry`

示例：
```typescript
import type { Tool, ToolContext, ToolResult } from "../types.js";
import { z } from "zod";

const parameters = z.object({ param: z.string() });

export const myTool: Tool = {
  name: "my_tool",
  description: "...",
  parameters,
  accesses: [{ resource: "example", action: "read" }],
  async execute(ctx: ToolContext, args: unknown): Promise<ToolResult> {
    const { param } = args as { param: string };
    return { success: true, output: `Result: ${param}` };
  },
};
```

### 5.2 修改 Agent 配置字段

Agent 类型在 `packages/shared/src/types/agent.ts`。新增字段后：

1. 在相关 repository 中处理序列化/反序列化
2. 在 `apps/web/pages/agents/[id].vue` 或 `apps/web/tests/components/agent-edit/*.vue` 中添加对应 UI
3. 更新测试

### 5.3 修改 ReAct 循环

- `services/engine/src/core/react/turn.ts` — `runTurn()` 主入口
- `services/engine/src/core/react/step.ts` — `executeLoopStep()` 单步执行

修改后需验证：
- 私聊正常输出
- 工具调用正常返回
- 循环能正确终止

### 5.4 新增 API 端点

1. 在 `services/engine/src/api/routes/` 下创建或修改路由文件。
2. 使用 Fastify 的 `schema` 选项添加 `summary` 和 `tags`，Swagger 会自动收录。
3. 在 `services/engine/src/api/server.ts` 中调用 `registerXxxRoutes(app, context)`。
4. 在 `services/engine/tests/api/` 添加对应集成测试。

示例：

```typescript
// services/engine/src/api/routes/example.ts
import type { FastifyInstance } from "fastify";
import type { ApiContext } from "../context.js";

export async function registerExampleRoutes(app: FastifyInstance, context: ApiContext) {
  app.get("/example", {
    schema: { summary: "Example endpoint", tags: ["example"], response: { 200: { type: "object" } } },
  }, async () => {
    return { ok: true };
  });
}
```

### 5.5 新增组件

1. 在 `apps/web/components/` 创建 `.vue` 组件。
2. 在页面中直接按名称使用（Nuxt 自动导入）。
3. 在 `apps/web/tests/components/` 添加测试，使用 `@nuxt/test-utils` 或 `@vue/test-utils`。

示例测试：

```typescript
import { describe, it, expect } from "vitest";
import { mount } from "@vue/test-utils";
import ChatView from "../../components/ChatView.vue";

describe("ChatView", () => {
  it("renders messages", () => {
    const wrapper = mount(ChatView, { props: { messages: [{ role: "user", content: "hi" }] } });
    expect(wrapper.text()).toContain("hi");
  });
});
```

## 6. 测试

```bash
# 运行所有测试
pnpm test

# 单独运行
pnpm --filter @mindcloud/engine test
pnpm --filter @mindcloud/web test

# 覆盖率报告
pnpm test:coverage

# Benchmark
pnpm bench
```

当前测试覆盖：
- `services/engine/tests/core/` — ReAct 循环、AgentWorker
- `services/engine/tests/api/` — REST / WebSocket API
- `services/engine/tests/memory/repositories/` — per-Agent 文档存储
- `services/engine/tests/tools/` — 工具注册与内置工具
- `services/engine/tests/config/` — 配置与加密
- `services/engine/tests/scheduler/` — 定时任务
- `services/engine/tests/blueprint/` — 蓝图工作流
- `services/engine/tests/conductor/` — 群聊编排
- `services/engine/tests/subagent/` — Subagent 调度
- `services/engine/tests/provider/` — LLM Provider

### 6.1 E2E 测试

使用 Playwright：

```bash
# 构建并启动 engine + web
pnpm build
pnpm --filter @mindcloud/engine start &
pnpm --filter @mindcloud/web start &

# 运行 E2E 测试

# 调试模式
pnpm test:e2e:ui
```

E2E 测试位于 `tests/e2e/`，覆盖创建 Agent、发送消息、验证回复等核心流程。
