# CloudMind-Zome 开发指南

> 版本：2.0 | 日期：2026-07-21
> 面向开发者的快速上手和调试指南。

---

## 1. 环境准备

### 1.1 要求与技术栈

**运行要求**：
- Node.js 22+
- Rust（版本见 `rust-toolchain.toml`，当前 1.88）
- protoc 27+

**技术栈**：
- 后端：Node.js 22 + Fastify 5
- 前端：Nuxt 3 + Vue 3 + Pinia + TypeScript
- 桌面：Tauri 2（Rust + WebView2）
- 侧车：Rust `crates/zome-sidecar`（gRPC）
- 包管理：pnpm workspace + Turborepo

### 1.2 安装依赖

```bash
pnpm install
```

### 1.3 启动开发环境

```bash
# Web 模式（同时启动 engine + web）
pnpm dev

# Tauri 桌面模式（需 Rust）
pnpm --filter @mindcloud/desktop dev
```

服务启动后：
- 前端：`http://localhost:3000`
- 后端 API：`http://127.0.0.1:8848`（Swagger UI：`http://127.0.0.1:8848/docs`）
- WebSocket：`ws://127.0.0.1:8848/ws/:agentId?sessionId=xxx`

> sidecar 在 Web 模式下**不是必需的**：没有它向量记忆会静默降级，其余功能正常。桌面模式由 Tauri 自动拉起 sidecar，sidecar 再守护 engine。

### 1.4 环境变量

| 变量 | 说明 | 默认值 |
|------|------|--------|
| `CLOUDMIND_DATA_DIR` | 运行时数据目录（配置、Agent 数据） | `~/.cloudmind-zome` |
| `CLOUDMIND_MASTER_KEY` | 用于加密 API Key 的主密钥；若未设置则自动生成 `.master-key` | 自动生成 |
| `CLOUDMIND_ALLOWED_ORIGINS` | CORS / WS Origin 白名单，多个用英文逗号分隔 | `http://localhost:3000,http://127.0.0.1:3000,http://localhost:1420` |
| `PORT` | engine HTTP 监听端口 | `8848` |
| `NODE_ENV` | 设为 `e2e` 时使用 Mock provider、CORS/WS Origin 全放行 | — |
| `ZOME_SIDECAR_ADDR` | sidecar gRPC 地址 | `127.0.0.1:50051` |
| `ZOME_PROTO_PATH` | zome.proto 路径覆盖 | 向上找 `crates/zome-sidecar/proto/zome.proto` |
| `ZOME_STARTUP_RECONCILE` | 启动对账（补归档热存储孤儿消息）；`false` 关闭 | `true` |

sidecar（Rust）侧另有：`ZOME_MASTER_KEY`（sidecar 加密密钥，注意与 engine 不是同一套）、`ZOME_NODE_PATH`、`ZOME_ENGINE_ENTRY`。

## 3. 启动流程详解

```
pnpm dev
  │
  ├── turborepo 并行/串行调度
  │
  ├── services/engine/src/bootstrap.ts
  │   ├── 加载 config.json、初始化 Repository
  │   ├── 实例化 SidecarClient（惰性连接，可选）
  │   ├── 组装 subagent / plan / worker 工厂
  │   ├── 注册 Fastify 路由（agents / chat / memory / actions / skills /
  │   │   compute / config / scheduler / blueprints / sessions / plans /
  │   │   subagents / logs + 2 个 WS handler）
  │   ├── 启动 Scheduler（5s 轮询）
  │   └── 监听 127.0.0.1:8848
  │
  └── apps/web
      └── nuxt dev → http://localhost:3000
```

桌面模式：

```
apps/desktop/src-tauri/src/main.rs
  │
  ├── 启动 Rust sidecar（zome-sidecar，gRPC :50051）
  │   └── sidecar supervisor 启动并守护 node engine（失败指数退避重启）
  │
  └── WebView2 加载 Nuxt 前端（Tauri 下 SSR 关闭，静态输出）
```

## 4. 调试技巧

### 4.1 查看日志

- engine 使用 pino 输出到 stdout；同时维护内存环形缓冲，可通过 `GET /logs` 或前端 LogPanel 查看
- 关键日志标记：
  - `AgentWorker started for {name}` — Worker 启动成功
  - `ReAct loop finished` — ReAct 循环结束
  - `Job execution failed` — Job 执行异常

### 4.2 查看 WebSocket 流量

浏览器 DevTools → Network → WS → 选择 `ws://127.0.0.1:8848/ws/...`

常见帧：
- 发送 `{ "text": "..." }` → 收到 `text.delta` / `thinking.delta` / `tool.call` / `tool.result` / `step.end`
- 审批：`tool.approval_request` → 回复 `tool.approval`
- 模式切换：发送 `session.set_mode` → 收到 `session.mode_changed`

### 4.3 检查 per-Agent 存储

```bash
ls ~/.cloudmind-zome/agents
# 每个 Agent 对应一个目录，内含 agent.json、messages.jsonl、memories.jsonl 等
```

## 5. 常见开发任务

### 5.1 添加新工具

1. 在 `services/engine/src/tools/builtin/` 下创建新文件
2. 实现 `Tool` 对象（定义名称、描述、Zod schema、execute 函数）
3. 在 `services/engine/src/tools/builtin/index.ts` 注册到内置工具列表

示例：
```typescript
import type { Tool, ToolContext, ToolResult } from "../types.js";
import { z } from "zod";

const parameters = z.object({ param: z.string() });

export const myTool: Tool = {
  name: "my_tool",
  description: "...",
  parameters,
  accesses: [{ resource: "file", action: "read" }], // resource: file | network | process | memory
  async execute(ctx: ToolContext, args: unknown): Promise<ToolResult> {
    const { param } = args as { param: string };
    return { success: true, output: `Result: ${param}` };
  },
};
```

> 写类/危险工具加 `requiresApproval: true`：交互式会话中需人工确认，无审批通道的调用方（定时任务、蓝图、subagent）会被自动拒绝。

### 5.2 修改 Agent 配置字段

Agent 类型在 `packages/shared/src/index.ts`（`AgentConfig`）。新增字段后：

1. 在相关 repository 中处理序列化/反序列化
2. 在 `apps/web/components/agent-edit/*.vue`（编辑器为 `AgentEditor.vue`）中添加对应 UI
3. 更新测试

> 例外：引擎侧消费的高级字段可不加 UI——`compressionModel` / `topicDetectionWindowMinutes` / `topicMessageThreshold` / `semanticSearchEnabled` / `semanticTopK` / `semanticMinScore` 目前仅在 `bootstrap.ts` 逐项透传（判空，同 `maxContextTokens` 模式），经 REST 直接写入 agent.json 生效。改 shared 后记得 `pnpm --filter @mindcloud/shared build`（engine/web 引用的是 dist）。

### 5.6 ContextPipeline 与话题压缩

- 管线本体：`services/engine/src/context/`（`pipeline.ts` 组装循环、`layers.ts` 层定义、`downgrade.ts` 降级步骤、`assembler.ts` 渲染、`semantic.ts` L4 检索器）
- 话题压缩：`services/engine/src/memory/topic/`（`detector.ts` 边界检测、`tracker.ts` 话题跟踪、`compressor.ts` LLM 压缩、`store.ts` `_compressed/` 读写、`queue.ts` 后台队列）
- 接线点：`services/engine/src/core/agent-worker.ts`（processQueue 内的检测/注入/归档触发）
- 新增/调整降级步骤：改 `downgrade.ts` 的步骤数组（顺序即 L5 → L4 → L6-ext → L3），并补 `tests/context/downgrade.test.ts` 的序列断言
- 相关测试：`tests/context/`（管线/检索）、`tests/topic/`（检测/压缩/落盘）、`tests/core/agent-worker.test.ts`（集成）

> 注意 score 语义：sidecar 返回**距离**（1-cosine），相似度换算统一在 `MemoryIndexer.search` 出口，下游不要直接消费 sidecar 原始 score。

### 5.3 修改 ReAct 循环

- `services/engine/src/core/react/turn.ts` — `runTurn()` 主入口（每轮先 `ContextPipeline.assemble`）
- `services/engine/src/core/react/step.ts` — 单步执行

修改后需验证：
- 私聊正常输出
- 工具调用正常返回
- 循环能正确终止
- 超预算时降级路径正确（`services/engine/tests/context/`）

### 5.4 新增 API 端点

1. 在 `services/engine/src/api/routes/` 下创建或修改路由文件。
2. 使用 Fastify 的 `schema` 选项添加 `summary` 和 `tags`，Swagger 会自动收录。
3. 在 `services/engine/src/api/server.ts` 中调用 `registerXxxRoutes(app, context)`。
4. 在 `services/engine/tests/api/` 添加对应集成测试。

示例：

```typescript
// services/engine/src/api/routes/example.ts
import type { FastifyInstance } from "fastify";
import type { ApiContext } from "../context.js";

export async function registerExampleRoutes(app: FastifyInstance, context: ApiContext) {
  app.get("/example", {
    schema: { summary: "Example endpoint", tags: ["example"], response: { 200: { type: "object" } } },
  }, async () => {
    return { ok: true };
  });
}
```

### 5.5 新增组件

1. 在 `apps/web/components/` 创建 `.vue` 组件。
2. 在页面中直接按名称使用（Nuxt 自动导入）。
3. 在 `apps/web/tests/components/` 添加测试，使用 `@nuxt/test-utils` 或 `@vue/test-utils`。

## 6. 测试

```bash
# 运行所有测试
pnpm test

# 单独运行
pnpm --filter @mindcloud/engine test
pnpm --filter @mindcloud/web test

# 覆盖率报告
pnpm test:coverage

# Benchmark
pnpm bench
```

- `services/engine/tests/api/` — REST / WebSocket API

### 6.1 E2E 测试

使用 Playwright，**无需手动启动服务**——`playwright.config.ts` 的 webServer 会自动运行 `scripts/start-e2e.mjs`（建临时数据目录、`NODE_ENV=e2e`、起 engine + web）：

```bash
pnpm test:e2e        # 运行
pnpm test:e2e:ui     # 调试模式
```

E2E 测试位于 `tests/e2e/`，覆盖聊天流程与日志面板流程。可用 `PLAYWRIGHT_CHANNEL=msedge` 或 `chrome` 指定系统浏览器。
