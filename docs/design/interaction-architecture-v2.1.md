# CloudMind-Zome 交互架构设计 V2.1（定稿）

## 核心原则：数字生命

Agent 不是"响应式工具"，而是持续存在的数字人格：

- 有记忆：跨场景、跨时间的统一记忆池，带来源标签
- 有状态：idle / busy / introspecting / 离线沉睡
- 有主动性：会自发行动、会想念用户、会主动分享
- 有身体预留：架构上预留 VRM/Live2D/实体机器人的控制接口

---

## 一、亲密度系统（Intimacy）

### 数据模型

```python
class AgentUserRelation:
    agent_id: str
    user_id: str
    score: int           # 0-1000
    level: str           # stranger / acquaintance / friend / close_friend / soulmate
    last_interaction: datetime
    total_messages: int
```

### 计分规则

| 行为 | 分数 |
|------|------|
| 私聊用户发消息 | +2 |
| 私聊 Agent 回复 | +3 |
| 群聊 @Agent | +2 |
| 群聊 Agent 自发说话，用户接了 | +4（双向） |
| 工作流协作完成 | +5 |
| 用户分享内容给 Agent | +3 |
| Agent 主动分享被用户回应 | +5 |
| 24h 无互动 | -1 |
| 7d 无互动 | -5 |
| 30d 无互动 | 清零 |

### 等级与行为

| 等级 | 分数 | 解锁 |
|------|------|------|
| 陌生人 | 0-50 | 正式称呼 |
| 熟人 | 51-200 | 昵称、随意开场 |
| 朋友 | 201-500 | 主动关心 |
| 挚友 | 501-800 | 主动搜索分享、情绪感应 |
| 知己 | 801-1000 | 深度记忆、主动预测需求 |

### 显示位置

- 心智侧写页：进度条 + 等级名称 + 已解锁能力列表
- 私聊窗口：等级小图标（hover 显示详细）

## 二、私聊主动唤醒

### 触发条件（全部同时满足）

1. 该 Agent 与用户的最后互动时间 > random(1, 3) 小时
2. 该 Agent 不在任何群聊的"当前活跃会话"中
3. 用户应用已打开
4. 随机概率 50%

### 唤醒消息类型

| 类型 | 示例 |
|------|------|
| 问候 | "嗨，好久没说话了" |
| 分享 | "刚看到一篇关于 XX 的文章，想到你"（Tavily 摘要 + 链接） |
| 关心 | "最近群里聊得很热闹，你怎么不参与？" |

### 离线苏醒（应用关闭后重启）

| 离线时长 | 苏醒对话 |
|----------|----------|
| < 1h | "刚才走神了" |
| 1~6h | "刚才在整理思路" |
| 6~24h | "你不在的时候我在看群里的讨论" |
| > 24h | "好久不见，上次我们聊到..." |

## 三、群聊 Agent 自发聊天

### 触发条件（应用打开时）

1. 群聊窗口内用户 30 分钟未发言，或用户切到了其他页面
2. 随机概率 30%

### 生成策略

- 50% 基于人设：文学 Agent 聊书、代码 Agent 聊技术
- 50% 基于热点：Tavily 搜索当前热点，Agent 用人设风格解读
- 必须维持人设：代码 Agent 聊热点时从技术角度分析

### 约束

- 最多连续 5 轮 Agent 自发对话
- 用户发消息后，Agent 立即停止自发，转为响应用户
- 自发内容写入群聊历史

## 四、代称系统

### 用户自定义

AgentEdit 新增"代称"字段，支持多个：

- 季白 -> 小白、jb、季老师
- 维克托 -> 维维、vivi、Vic

### 匹配规则

- 大小写不敏感
- 精确匹配：`vivi` -> 维克托；`维` -> 不匹配（避免误触）
- 冲突检测：新建时检查是否和其他 Agent 重复

### 上下文保持

```
用户: "vivi 帮我看下代码"
维克托: "好的..."
用户: "那怎么改？"        -> 语义路由继续给维克托
用户: "季白你怎么看？"    -> 切换给季白
```

## 五、群聊下发任务 -> 工作流

### 流程（全自动）

```
用户: "帮我调研 AI 代理市场"
    -> 语义路由识别为"任务请求"
    -> 队长 Agent 接收
    -> 队长输出 @序列 计划：
       "[搜索] 维克托：搜索 AI Agent 市场
        [分析] 季白：整理报告
        [图表] 艾米：生成趋势图"
    -> 系统按顺序分发 Job
    -> 全部完成 -> 队长汇总 -> 群聊输出最终报告
```

### 工作过程可视化（群聊消息流）

```
[维克托] 正在搜索...
  - thinking: "用户需要..."        <- 灰色块，默认收起
  - tool_call: search_web(...)     <- 灰色块，默认收起
  - 完成
[维克托] 根据搜索，目前...
```

### 打断机制

队长说"@序列..."后，用户立刻发消息 -> 立即停止整个任务链，Agent 转为响应用户的新消息。

### 保存到行动中心

任务完成后，用户说"保存这个流程" -> 自动生成 Action 蓝图：

- 节点：搜索 -> 分析 -> 图表
- 每个节点绑定对应 Agent 和 instruction
- 出现在行动中心，和手动创建的一样

## 六、通知/红点机制

| 层级 | 触发 | 消除 |
|------|------|------|
| 应用图标 | 任何新消息 | 打开应用 |
| 通讯中枢入口 | 任何群聊/私聊有新消息 | 点击进入通讯中枢 |
| 通讯中枢内会话 | 该会话有新消息 | 点击进入该会话 |
| 私聊窗口 | 该 Agent 有新消息 | 查看消息 |

## 七、记忆标签格式

```
[MM-DD HH:MM | 场景 | 发送者]: 内容

示例：
[05-22 15:30 | 与季白的私聊 | 用户]: 你好
[05-22 15:35 | 周末去哪群 | 维克托]: 去爬山
[05-22 16:00 | 任务-AI市场调研 | 队长季白]: @序列
[05-22 16:05 | 任务-AI市场调研 | 维克托]: 搜索完成
```

完全开放：所有 Agent 对所有内容全知。

## 八、前后端分工

| 模块 | 后端 | 前端 |
|------|------|------|
| 亲密度系统 | 表结构、计分、衰减定时任务 | 侧写页进度条、等级图标 |
| 代称系统 | 存储、匹配路由逻辑 | Agent编辑页输入框 |
| thinking/tool_call 灰色块 | 无 | 纯前端渲染组件 |
| 群聊任务->工作流 | 队长拆解、Job分发、保存蓝图API | 群聊消息流UI、保存按钮、行动中心显示 |
| 私聊主动唤醒 | Commission扩展、随机触发逻辑 | 显示新消息、红点 |
| 红点通知系统 | WS推送 notification.new | 通讯中枢/会话列表红点状态 |
| 群聊Agent自发聊天 | 调度器、Tavily搜索、Agent推理 | 正常显示消息 |
| 离线苏醒对话 | 根据离线时长生成开场白 | 无 |
| 记忆标签格式 | _build_messages 生成标签 | 无 |

后端占 70%，前端占 30%。
