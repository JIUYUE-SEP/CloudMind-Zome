## 1. 项目定位

CloudMind-Zome 是一个**单用户本地桌面应用**（也可作为 Web 应用运行），核心定位是"多 Agent 协作平台"。

- **单用户**：无登录/注册流程，硬编码 `user_id="user"`，所有数据本地存储
- **本地优先**：运行时数据落在 `~/.cloudmind-zome/`（或 `%LOCALAPPDATA%\com.cloudmind-zome.app`）
- **桌面封装**：Tauri 2（Rust + WebView2），内嵌 Python 后端，退出时通过 Windows Job Object 清理子进程

### 1.1 核心功能（当前已实现）

| 功能 | 说明 | 关键代码 |
|------|------|----------|
| 私聊 | 用户与单个 Agent 一对一对话，流式输出 | `ws_handlers.py:49` |
| 群聊 | 多 Agent 群组讨论，@mention 路由 | `group_chat_router.py` |
| 心智互聊 (Intermind) | Agent 间多轮讨论，由 Conductor 编排 | `conductor_service.py:68` |
| Agent 间私信 | Agent 通过工具调用向其他 Agent 发消息 | `agent_communication.py:23` |

| 算力平台 | 管理 LLM Provider（API Key、Base URL、模型列表） | `compute.py` |

## 4. 核心机制

### 4.1 AgentWorker — 单一数字生命

每个 Agent 对应全局唯一的 `AgentWorker`（`app/services/agent_worker.py:42`）：

- **一个 `asyncio.Task`** — 串行处理所有 Jobs（`run()` 方法，`agent_worker.py:246`）
- **一个 `asyncio.Queue`** — FIFO 队列，不区分优先级（`__init__` 中 `ensure_queue`，`agent_worker.py:52`）
- **一个 `ReActAgent` 实例** — 永不重建，持有场景隔离的记忆 `_messages`（`agent_worker.py:54`）
- **一个状态** — idle / busy，由 Worker 单点维护（`_set_db_status`，`agent_worker.py:451`）

**Job 类型**（`app/services/job_queue.py`）：
- 正常对话（`stream`）— 流式输出 content / thinking / tool_call
- 仅写入记忆（`ingest_only`）— 群聊消息广播，只写入记忆不生成回复（`agent_worker.py:312`）

### 4.2 ReAct 循环

```
用户消息 → 加入 _messages → ContextPipeline 组装 Prompt → LLM 流式调用 → 解析响应
                                                              ↓
                                                    ┌─────────┴─────────┐
                                                    ↓                   ↓
                                              [普通回复]           [Tool Calls]
                                                    ↓                   ↓
                                              保存并结束          执行工具 → 结果加入 _messages
                                                                          ↓
                                                                  继续下一轮 LLM
```

**流式输出**：`transport.stream()` 逐 token 推送，通过 `AgentEvent` 事件类型：
- `thinking` — 推理内容（折叠显示）
- `content` — 正文内容
- `tool_call` — 工具调用
- `tool_result` — 工具执行结果
- `done` — 流结束

### 4.3 Context Pipeline — 六层组装

`ContextPipeline`（`engine/context/context_pipeline.py`）每轮 LLM 调用前按 **L1→L6** 组装 prompt：

| 层级 | 内容 | 降级策略 |
|------|------|----------|
| L1 | Mind 文件（SOUL.md / AGENT.md / USER.md / PROFILE.md）+ 平台能力 | 不降级 |
| L2 | 群聊 sender 前缀 | 不降级 |
| L3 | Hot Context（当前场景最近 N 条消息） | 20→15→10→5 截断 |
| L4 | 语义检索结果（zvec 跨场景 top-K） | 10→5→3→0 从低分去掉 |
| L5 | 话题摘要（`_compressed/*.md`） | 多条合并成一条概要 |
| L6 | 工具描述 | 不降级 |

**降级顺序：L5 → L4 → L3**，超限时自动触发。L1 / L2 / L6 永不动。

### 4.4 记忆系统 — 三层架构

```
┌─────────────────────────────────────────────┐
│  Hot Context  (ReActAgent._messages)         │
│  - 按 source_id 场景隔离，内存中直接访问     │
│  - 切换场景时清空重载                         │
├─────────────────────────────────────────────┤
│  Semantic Memory  (zvec 向量)               │
│  - 每条消息自动 embedding（per-Agent Embedder）│
│  - 跨场景语义相似度检索                       │
│  - 时间衰减打分，低于阈值过滤                 │
├─────────────────────────────────────────────┤
│  Topic Summaries  (_compressed/*.md)       │
│  - TopicMarker 检测话题切换                  │
│  - CompressionWorker 异步压缩生成            │
│  - 按修改时间排序，Pipeline L5 注入          │
└─────────────────────────────────────────────┘
```

### 4.5 工具系统

Agent 可调用 7 个工具集（`toolset`），通过 `@tool_registry.register()` 自动注册：

| Toolset | 工具 | 功能 |
|---|---|---|
| `web` | `search_web`, `generate_image` | Tavily 搜索、生图（DashScope/SiliconFlow/OpenAI 兼容） |
| `file` | `read_file`, `write_file`, `edit_file`, `delete_file`, `share_file` | 文件操作（有路径白名单） |
| `code` | `python_execute` | 执行 Python 代码 |
| `shell` | `shell_command` | 执行 Shell 命令 |
| `comms` | `send_private_message`, `report_workflow_progress` | Agent 间私信、工作流进度 |
| `group` | `stay_silent` | 群聊中 Agent 决定不回复 |
| `project` | `list_project_docs`, `search_project_docs` | 项目知识库查询 |

**工具权限**：`main.py:162` 的 `_tool_permission_checker` 是全局唯一权限钩子，通过 `is_safe_path` 检查文件操作路径。

## 5. 通信架构

### 5.1 WebSocket 协议

单连接，多路复用。`ws.py` 仅做路由分发（<50行），业务逻辑在 `ws_handlers.py`。

**Client → Server**：
- `chat.send` — 发送消息
- `agent.stop` — 暂停私聊 Agent
- `chat.typing` — 输入状态

**Server → Client**：
- `chat.message` — 消息内容（含 tool_calls / reasoning）
- `chat.thinking` — 推理块
- `chat.tool_call` — 工具调用
- `agent.status` — Agent 状态变更（idle / busy）
- `intermind.start` / `intermind.end` — 心智互聊起止标记
- `action.progress` — 工作流进度
- `notification.new` — 系统通知

### 5.2 群聊路由

```
用户消息
    │
    ▼
┌─────────────────────┐
│ GroupChatRouter     │
│ - @mention 精确路由  │
│ - @所有人 / @all     │
│ - 语义意图路由       │
│ - 随机兜底           │
└──────────┬──────────┘
           │
           ▼
    选中的 Agent(s)
           │
           ▼
    并行 dispatch_job()
           │
           ▼
    各 Agent Worker 串行回复
```

### 5.3 心智互聊 (Intermind)

群聊设置 `intermind_enabled=true`（默认关闭）时触发：

```
用户消息 → GroupChatRouter → 选中 Agent 回复 → ConductorService.maybe_trigger_intermind()
                                                              │
                                                              ▼
                                                    ┌─────────────────┐
                                                    │  QAState 内存状态 │
                                                    │ - 轮数计数      │
                                                    │ - 历史记录      │
                                                    │ - max_rounds    │
                                                    └────────┬────────┘
                                                             │
                                                             ▼
                                                    随机选另一个 idle Agent
                                                             │
                                                             ▼
                                                    EngineBridge.stream_chat()
                                                             │
                                                             ▼
                                                    WS 推送 intermind.start
                                                    → 每轮内容 → intermind.end
```

- **轮数控制**：`intermind_rounds`（默认 4 轮）
- **触发时机**：Agent 回复后自动触发，不是用户主动触发
- **前端显示**：`intermind.start/end` 帧包裹中间内容，可折叠

### 5.4 Agent 间私信

通过 `send_private_message` 工具实现（`engine/tools/comms/private_message.py`）：

```
Agent A (send_private_message 工具调用)
    │
    ▼
engine/tools/comms/dispatchers.py (get_send_private_message)
    │
    ▼
app/services/agent_communication.py:dispatch_private_message()
    │
    ▼
创建 AgentJob → dispatch_job(to_agent_id) → 目标 Agent Worker 队列
    │
    ▼
目标 Agent 处理 → 返回 reply → 原 Agent 的 tool_result
```

- **source="private"**，`source_id="agent2agent:{from}:{to}"`
- **阻塞等待**：`asyncio.Future` 等待目标 Agent 回复，默认 120s 超时
- **无循环检测**：A→B→A 模式可能无限循环（当前依赖工具调用次数限制）

## 8. 错误处理与恢复

### 8.1 错误分类

| 类型 | 示例 | 策略 |
|------|------|------|
| 可重试 | RateLimit, Timeout | 指数退避重试（最多 3 次） |
| 可降级 | API 故障, 认证失败 | 切换 fallback provider |
| 不可恢复 | 模型不支持, 参数错误 | 直接报错 |

### 8.2 Provider 降级链

**per-Agent 配置**：`agents.fallback_chain`（JSON 列表），定义备选 provider 列表。

```
LLM 调用失败时:
  1. 判断错误类型（classify_error）
  2. 可重试 → 指数退避重试
  3. 不可重试 → 切换 fallback_chain 中下一个 provider
  4. 全部失败 → 返回错误给前端
```

### 8.3 SmartStop

防止 Agent 陷入无限循环（`engine/config/models.py:SmartStopConfig`）：
- `max_turns` — 最大轮数（默认 50）
- `max_tokens` — 最大 token 数（默认 200K）
- `timeout_seconds` — 超时（默认 600s）
- `no_progress_rounds` — 无进展轮数（默认 3）
- `loop_detect_rounds` — 循环检测（默认 2）

## 9. 安全模型

> CloudMind-Zome 是**单用户本地应用**，以下安全建议针对本地桌面场景。

| 风险 | 现状 | 建议 |
|------|------|------|
| 单用户无隔离 | 无多用户支持，所有 Agent 共享同一用户上下文 | 如需多用户，需扩展 `auth.ts` 和 `user.py` |
| 文件系统逃逸 | `write_file` 有路径白名单（`is_safe_path`） | 增加 chroot 或沙箱 |
| 代码执行 | `python_execute` / `shell_command` | 增加确认弹窗或禁用开关 |
| API Key 存储 | DB 中加密存储（`api_key_encrypted`），YAML 为运行时副本 | 支持环境变量覆盖 `${ENV_VAR}` |
| WS 无鉴权 | 任意客户端可连接（本地开发） | 生产环境增加 token 验证 |
| SQLite 并发 | WAL 模式但单进程 | 生产环境迁移 PostgreSQL |

## 10. 已知限制

| 限制 | 现状 | 影响 |
|------|------|------|
| Agent 首次回复慢 | Worker 冷启动（查 DB + 建 Transport + Embedder） | 首次对话有延迟 |
| 群聊多 Agent 并行 | N 个 Agent 同时查 DB、调 LLM | 并发控制 3 个 |
| 图片 base64 传输 | 大图片导致 WS 帧过大 | 限制 5MB |
| 向量检索 | zvec 本地文件，大数据量时性能下降 | 未来迁移 Milvus/Pinecone |
| 前端 systemLogs 无持久化 | `useWebSocket.ts:24` 为内存数组 | 刷新页面丢失 |
| Agent 间循环 | 无 MAX_HOPS / 循环检测 | A→B→A 可能无限循环 |
| 公共 Skill 池 | 无 `pools/skills/` 目录 | 仅支持 Agent 私有 Skill |
