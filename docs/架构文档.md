## 1. 项目定位

CloudMind-Zome 是一个**单用户本地桌面应用**（也可作为 Web 应用运行），核心定位是"多 Agent 协作平台"。

- **单用户**：无登录/注册流程，硬编码 `user_id="user"`，所有数据本地存储
- **本地优先**：运行时数据落在 `~/.cloudmind-zome`（Windows 上为 `%USERPROFILE%\.cloudmind-zome`），可用环境变量 `CLOUDMIND_DATA_DIR` 覆盖
- **桌面封装**：Tauri 2（Rust + WebView2），内嵌 **Node.js 引擎 + Rust sidecar**

## 4. 核心机制

> 本节及以下章节已按当前 Node.js + Rust 架构修正；不确定或尚未明确的实现细节标记为 `TODO: 待更新`。

### 4.1 AgentWorker — 单一数字生命

每个 Agent 对应全局唯一的 `AgentWorker`（`services/engine/src/core/agent-worker.ts`）：

- **一个内部队列** — FIFO 数组 `queue`，串行处理所有 Jobs
- **一个状态** — `idle` / `busy` / `paused`，由 Worker 单点维护
- **`runTurn()` 调用** — 每轮通过 `services/engine/src/core/react/turn.ts` 执行 ReAct 步骤

**Job 类型**（`services/engine/src/core/agent-worker.ts`）：
- 正常对话 — 流式输出 content / thinking / tool_call
- 定时任务（`runScheduledTask`）— 由 Scheduler 触发，先持久化用户消息再入队

### 4.2 ReAct 循环

```
用户消息 → 加入 _messages → ContextPipeline 组装 Prompt → LLM 流式调用 → 解析响应
                                                              ↓
                                                    ┌─────────┴─────────┐
                                                    ↓                   ↓
                                              [普通回复]           [Tool Calls]
                                                    ↓                   ↓
                                              保存并结束          执行工具 → 结果加入 _messages
                                                                          ↓
                                                                  继续下一轮 LLM
```

**流式输出**：`LLMProvider.chat()` 逐 token 推送，通过 `LLMEvent` 事件类型：
- `thinking.delta` — 推理内容（折叠显示）
- `text.delta` — 正文内容
- `tool.call` — 工具调用
- `tool.result` — 工具执行结果
- `step.end` — 单步结束

### 4.3 Context Pipeline — 六层组装

> TODO: 待更新 — 当前实现尚未包含完整的六层 ContextPipeline。`services/engine/src/core/react/` 仅基于传入的 `messages` 与工具描述调用 LLM，语义检索、话题压缩等能力待接入 Rust sidecar 后补充。

`ContextPipeline`（`TODO: 待更新`）每轮 LLM 调用前按 **L1→L6** 组装 prompt：

| 层级 | 内容 | 降级策略 |
|------|------|----------|
| L1 | Agent 配置（`agent.json` / 系统 prompt）+ 平台能力 | 不降级 |
| L2 | 群聊 sender 前缀 | 不降级 |
| L3 | Hot Context（当前 session 最近 N 条消息） | 20→15→10→5 截断 |
| L4 | 语义检索结果（zvec 跨场景 top-K） | 10→5→3→0 从低分去掉 |
| L5 | 话题摘要 | 多条合并成一条概要 |
| L6 | 工具描述 | 不降级 |

**降级顺序：L5 → L4 → L3**，超限时自动触发。L1 / L2 / L6 永不动。

### 4.4 记忆系统 — 当前实现

```
│  语义检索 / 话题压缩                         │
```

### 4.5 工具系统

Agent 可调用的内置工具位于 `services/engine/src/tools/builtin/`，经 `bootstrap.ts` 按 `agentConfig.tools` 名单启用：

| 工具 | 文件 | 功能 |
|---|---|---|
| `read_file` | `builtin/read.ts` | 读取工作区文件 |
| `write_file` | `builtin/write.ts` | 写入工作区 `files/` 子目录（code 模式下为 projectRoot，保护名单仍生效） |
| `edit_file` | `builtin/edit_file.ts` | 编辑文件 |
| `list_files` | `builtin/list_files.ts` | 列目录（`recursive` 参数未实现） |
| `bash` | `builtin/bash.ts` | 白名单命令（ls/cat/echo/pwd/mkdir/touch），禁 shell 元字符与脚本执行 |
| `run_command` | `builtin/run_command.ts` | **无沙箱**任意 shell（code 模式），cwd 限制不是安全边界，timeout 上限 600s |
| `dispatch_subagent` | `builtin/dispatch_subagent.ts` | 借用其他 Agent 执行子任务（前台/后台） |
| `web_search` | 未实现（`tavilyApiKey` 配置已预留） | Tavily 搜索 |
| `generate_image` | 未实现 | 图像生成 |

**工具权限**：写入工具通过 `resolveAllowedWritePath` 限制只能写入工作区 `files/` 子目录，并保护 `agent.json`、`messages.jsonl`、`config.json`、`.master-key` 等关键文件（code 模式同样生效）。标记 `requiresApproval` 的工具（write_file/edit_file/bash/run_command）执行前需人工审批——交互式 WS 会话中前端弹出 inline 确认（`tool.approval_request` → `tool.approval`，60s 超时视为拒绝，可选"本会话不再询问"）；无审批通道的调用方（定时任务、蓝图、subagent）一律拒绝。

## 5. 通信架构

### 5.1 WebSocket 协议

单连接，多路复用。入口为 `services/engine/src/api/ws/handler.ts`，按 session 路由消息；`services/engine/src/api/ws/session-handler.ts` 管理 session 生命周期。

**Client → Server**：
- `chat.send` — 发送消息
- `agent.stop` — 暂停私聊 Agent
- `chat.typing` — 输入状态

**Server → Client**：
- `chat.message` — 消息内容（含 tool_calls / reasoning）
- `chat.thinking` — 推理块
- `chat.tool_call` — 工具调用
- `agent.status` — Agent 状态变更（idle / busy）
- `intermind.start` / `intermind.end` — 心智互聊起止标记
- `action.progress` — 工作流进度
- `notification.new` — 系统通知

### 5.2 群聊路由

```
用户消息
    │
    ▼
┌─────────────────────┐
│ GroupChatRouter     │
│ - @mention 精确路由  │
│ - @所有人 / @all     │
│ - 语义意图路由       │
│ - 随机兜底           │
└──────────┬──────────┘
           │
           ▼
    选中的 Agent(s)
           │
           ▼
    并行 dispatch_job()
           │
           ▼
    各 Agent Worker 串行回复
```

## 7. 配置系统

### 7.1 引擎配置（`config.json`）

运行时从 `CLOUDMIND_DATA_DIR/config.json` 加载，由 `ConfigRepository`（`services/engine/src/config/repository.ts`）管理。当前配置包含 Provider 列表与 `settings.memory`：

```json
{
  "providers": [],
  "settings": {
    "memory": {
      "compactThreshold": 0.8,
      "keepRecent": 3,
      "hotMemoryLimit": 10,
      "warmMemoryLimit": 20
    },
    "tavilyApiKey": "tvly-..."
  }
}
```

> 凭据（Provider API Key、`tavilyApiKey`）以 `enc:` 前缀调用 `services/engine/src/config/crypto.ts` AES-256-GCM 加密后落盘。

### 7.2 Provider 配置

Provider 配置统一存放在 `config.json` 的 `providers` 数组中，由算力平台界面（`apps/web/pages/compute.vue`）通过 REST API（`services/engine/src/api/routes/compute.ts`）读写。

- **前端入口**：`apps/web/pages/compute.vue`
- **后端路由**：`services/engine/src/api/routes/compute.ts`
- **配置仓库**：`services/engine/src/config/repository.ts`
- **凭据加密**：`services/engine/src/config/crypto.ts`（AES-256-GCM，主密钥来自 `CLOUDMIND_MASTER_KEY` 或自动生成的 `.master-key`）
- **启动加载**：`services/engine/src/bootstrap.ts` 加载 `config.json` 并初始化 Provider

### 7.3 数据目录

```
DATA_DIR/  (~/.cloudmind-zome/)
├── config.json            # 全局配置（含 Provider、内存参数）
├── .master-key            # 自动生成的 AES 主密钥（权限 0o600）
├── agents/{agent_id}/     # Agent 工作区
│   ├── agent.json         # Agent 元数据
│   ├── messages.jsonl     # 会话消息
│   ├── memories.jsonl     # 长期记忆
│   ├── scheduler.jsonl    # 定时任务日志
│   ├── actions.jsonl      # 工作流执行记录
│   └── files/             # 工具可读写目录
└── uploads/               # 上传文件
```

## 8. 错误处理与恢复

### 8.1 错误分类

| 类型 | 示例 | 策略 |
|------|------|------|
| 可重试 | RateLimit, Timeout | 指数退避重试（最多 3 次） |
| 可降级 | API 故障, 认证失败 | 切换 fallback provider |
| 不可恢复 | 模型不支持, 参数错误 | 直接报错 |

### 8.2 Provider 降级链

> TODO: 待更新 — 当前代码**未实现**错误分类、指数退避重试与 `fallback_chain`。`AgentConfig` 无 `fallback_chain` 字段，LLM 调用失败直接报错。以下内容为设计目标。

**per-Agent 配置**：`agents.fallback_chain`（JSON 列表），定义备选 provider 列表。

```
LLM 调用失败时:
  1. 判断错误类型（classify_error）
  2. 可重试 → 指数退避重试
  3. 不可重试 → 切换 fallback_chain 中下一个 provider
  4. 全部失败 → 返回错误给前端
```

## 9. 安全模型

> CloudMind-Zome 是**单用户本地应用**，以下安全建议针对本地桌面场景。

| 风险 | 现状 | 建议 |
|------|------|------|
| 单用户无隔离 | 无多用户支持，所有 Agent 共享同一用户上下文 | 如需多用户，需扩展 `services/engine/src/api/routes/sessions.ts` 等 |
| 文件系统逃逸 | `write_file` 限制在 `files/` 子目录（`services/engine/src/tools/builtin/write.ts`） | 增加 chroot 或沙箱 |
| 代码执行 | `run_command` 为**无沙箱**任意 shell（`bash` 工具是白名单，不是任意执行） | 写类工具（write_file/edit_file/bash/run_command）已接入人工审批：WS 会话内 inline 确认，60s 超时拒绝；蓝图/定时任务等非交互路径无审批通道，危险工具一律拒绝 |
| API Key 存储 | `config.json` 中 AES-256-GCM 加密（`services/engine/src/config/crypto.ts`） | 通过 `CLOUDMIND_MASTER_KEY` 覆盖主密钥 |
| SSRF 防护 | Provider `baseUrl` 已校验，但可被 `[::1]` 等边角绕过，且不防 DNS 重绑定 | 完善 IP 段覆盖与 DNS 解析校验 |
| WS 鉴权 | 握手已校验 Origin（`services/engine/src/api/ws/validation.ts`），无 token 鉴权 | 生产环境增加 token 验证 |

## 10. 已知限制

| 限制 | 现状 | 影响 |
|------|------|------|
| Agent 首次回复慢 | Worker 冷启动（加载配置、初始化 Provider） | 首次对话有延迟 |
| 群聊多 Agent 并行 | N 个 Agent 同时查 DB、调 LLM | 并发控制 3 个 |
| 图片 base64 传输 | 大图片导致 WS 帧过大 | 限制 5MB |
| 向量检索 | zvec 本地文件，大数据量时性能下降 | 未来迁移 Milvus/Pinecone |
| 前端 systemLogs 无持久化 | `useEngineClient.ts` 为内存数组 | 刷新页面丢失 |
| 公共 Skill 池 | 无 `pools/skills/` 目录 | 仅支持 Agent 私有 Skill |
