### Major（2 条）

**Major-1（P3-6 引入）retire 后 enqueue 无防护：孤儿 job 回潮 + 注册表死锁，agent 全通道静默挂起直到重启。**

可达窗口（resolve 与 enqueue 之间有 await 的路径）：
- 群聊：`session-handler.ts:208` 解析 → `:213` `await listBySession` → `:219` enqueue；
- scheduler：`scheduler.ts:74` 解析 → `runScheduledTask` 内 `await append`（`agent-worker.ts:135-153`）→ `:155` enqueue。
（私聊 `handler.ts:173→179`、subagent `bootstrap.ts:87→93`、blueprint `engine.ts:92→126` 之间无 await，窗口闭合。）
触发需要"配置变更恰好落在窗口内"，频率低，但后果是整体静默锁死。修法方向：enqueue 检查退役标志并立即 settle（与 retire 同构的终帧+onDone），或 retire 与 enqueue 共用一把 per-worker 锁。

**Major-2（P3-6 宣称不成立）WorkerRegistry 并发 create 不去重：双 worker 并存，"不并发交错/不重复创建"在群聊并发下失守；create 期间到达的 retire 丢失。**
`getOrCreate`（`worker-registry.ts:40-57`）在 create 执行期间既不在 `workers` 占位也不在 `retiringWorkers` 占位：两个并发调用（无 existing、无 retiring——包括排空刚结束的瞬间）都通过 `:41`、`:46-50` 检查 → 各跑各的 `create()` → 两个活 worker，后到 set 覆盖先到（`:55`）。群聊路径无串行 chain（`session-handler.ts:101` `void handleMessage`，对比私聊 `handler.ts:56-63` 有 chain），两条消息在排空等待期间并发 await 同一 retiring promise，醒后**确定性**双双创建——commit 宣称的"等待期间并发调用在排空后共享同一个新 worker（不重复创建）"不成立（`worker-registry.test.ts` 只测了串行共享）。败者 worker 是未退役的活实例，会继续跑持有者手上的 job：两个 turn 并发交错 + TopicTracker 分叉，即 P2(a)(b) 宣称消除的现象在窗口内复现（影响瞬时——持有者下次重新解析后归一，但交错与分叉已发生）。
附带缺陷：create 执行期间到达的 retire 因 `workers` 为空直接返回（`:27-28`），新 worker 可能按 PUT 之前的配置装配（`bootstrap.ts:129` 的 get 时机），该次配置变更被静默吞掉直到下次变更。
