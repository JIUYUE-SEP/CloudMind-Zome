## P2-1：chat 模式路径校验复用 resolveProjectPath 堵 junction 逃逸（f7df776）

**原问题**：chat 模式（无 projectRoot 的 fallback 分支）read_file/write_file 只有词法校验、无 realpath，预置 junction/symlink 后可读/写穿 workspace 边界（基线 路径 Major-1/2，docs/reviews/2026-07-23-full-review-安全.md:60-89）。

**修复方案**：删除 read.ts/write.ts 各自的词法-only 实现，fallback 与 code 模式统一走 `resolveProjectPath`（自带 realpath 二次比较），并新增 win32 设备保留名拒绝（services/engine/src/tools/builtin/read.ts:10、write.ts:36-38、project-paths.ts:9,62-82）。

**验证结果：真的修好。**

逐项核验：

1. junction/symlink 真被 realpath 拦了。校验链：词法边界检查（project-paths.ts:72-74）→ `fs.realpath(resolvedRoot)`（:78）→ `realpathNearest(fullPath)`（:79）→ 对两个 realpath 后的路径做包含性比较（:80-82），比较对象不是原始路径。win32 真实 junction 下新增测试「fallback 下 junction 逃逸被拒绝」「junction 写穿被拒绝」通过（tests/tools/builtin.test.ts，36/36）。旧实现无残留。
2. realpathNearest 祖先回溯正确。回溯（project-paths.ts:37-52）只对最近已存在祖先 realpath，尾部拼回词法段；包含性比较的对象是 realRoot，即使回溯到文件系统根也必然落在 realRoot 外而被拒；root 不存在时 realpath 直接抛错，fail-closed。
3. 正常 files/ 路径无误伤：workspace 内 junction 指向 workspace 内仍可读、`files/notes.md` 可读、多级新文件可写，均有测试覆盖。
4. 保留名正则 `^(con|prn|aux|nul|com[1-9]|lpt[1-9])(\..*)?$`（project-paths.ts:9）是精确匹配 + `名.任意扩展`，非 startsWith。实测：`con.txt`/`con.` 拒绝（符合 win32 真实语义），`console`/`connect.log`/`com1x`/`com10`/`lpt`/`mycon.txt` 全部放行。任务书担心的误伤不存在。

6. 旁路排查：chat 模式工具集仅 7 个内置工具（builtin/index.ts:10-12），接受文件路径的只有 read/write（已修）；bash 白名单禁斜杠/`..`/绝对路径（bash.ts:20-35），无法构造穿越参数。

**发现问题**：Minor-6（files/ 根替换残余，见问题清单）。
