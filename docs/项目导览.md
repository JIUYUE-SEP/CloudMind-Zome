## 一、这是什么

CloudMind-Zome（仓内简称 CMZ）是一个**纯 Web 形态的"人形"系统**——你在浏览器里养若干个有名字、有人格、有记忆的 AI 角色（仓内叫 **Agent / 人形**），跟它们私聊、拉群聊、让它们互相写信、派它们干活。

它不是一个聊天框套壳。它的核心命题是：**让 AI 角色像"活的"一样持续存在**——有人格文件、有长期记忆、会自己管理上下文、会定时干活、会互相社交。为了这个命题，仓里长出了一整套机制，这套机制就是新手最容易迷路的地方。

**形态三分件：**

- **engine**（Node.js 引擎，核心中的核心）：跑在 `127.0.0.1:8848`，管对话循环、记忆、工具、调度、REST/WS 接口。内部是 Cordis 插件化架构，22 个内部插件 + 外部插件体系。
- **web**（Nuxt 前端）：跑在 `localhost:3000`，聊天界面 + 各种管理面（设置、算力、蓝图、子页面群）。
- **sidecar**（Rust，可选性能组件）：向量索引专用进程，管"语义检索"的算力。不跑它系统照常工作，只是跨会话语义记忆静默关闭。

**一句话主循环**：你发一条消息 → engine 里该人形的专属 **worker** 排队接单 → 组装一坨"上下文"发给 LLM → LLM 边说边可能调工具 → 结果落盘、记忆归档 → 流式推回你的浏览器。其余 90% 的代码都在给这个循环做三件事：**省 token（上下文成本）、不丢东西（持久化与对账）、不失控（审批与降级）**。

## 二、黑话辞典（按域分组，全专属词汇解释）

### 2.1 人格与心智

- **Agent / 人形**：系统里的一个 AI 角色。有 id、名字、人设（persona）、模型配置、工具白名单、记忆文件。不是"一个 prompt"，是一个有持久状态的实体。
- **SOUL.md**：人形的人格核心文件（你是谁、性格、说话方式）。每个 Agent 一份，存在它的工作区里。每轮对话都注入，**永不裁剪**。
- **MIND.md**：人形的"经验档案"。系统在话题压缩时会顺手把"学到的东西"沉淀进去（带置信度），后续对话相关时自动召回。可以理解为"她自己写的读书笔记"。
- **心智（mind）**：SOUL + MIND 的合称，引擎里有专门的 mind 插件管这套文件。
- **傀儡（puppet）**：一种一次性的"分身"。主人形派生它去干一个子任务，它没有人格、没有记忆、用完即弃，但能用主人的模型和工具。设计目的：干脏活不污染主人格。
- **蓝图（blueprint）**：可视化编排的工作流（开始 → LLM → 工具 → 结束四种节点的线性链）。给"非人形"的自动化任务用的，比如定时跑一个固定流程。
- **瞬态回合（ephemeral）**：蓝图这类"非人形流量"打的标记——它们干活不写入任何人形的记忆和话题，防止人格历史被机器流量污染。

### 2.2 上下文体系（全仓最厚的机制区）

- **上下文（context）**：每轮发给 LLM 的全部输入。它有预算（token 上限），超了就得砍，砍谁不砍谁是本仓一套精密设计。
- **ContextPipeline（上下文管线）**：组装上下文的分层流水线。把输入分成 L1–L6 六层，超预算时按固定顺序降级。
- **L1**：人格层（SOUL + 安全准则 + 技能目录 + 按需工具目录）。**永不降级**。
- **L2**：@提及提醒层。已废弃删除（从来没有生产者）。
- **L3**：热上下文——当前会话的近期消息。降级时从最旧的开始截断。
- **L4**：语义检索结果——跨会话"相似记忆"（见 2.6 sidecar）。降级时保留高相关的。
- **L5**：话题摘要——旧话题被压缩后的摘要（见"话题压缩"）。降级时先丢最旧的。
- **L6**：工具定义。又分两档：**L6-core**（15 件内置工具，永不裁）和 **L6-ext**（MCP/外部插件的动态工具，可先砍）。
- **水位（watermark）**：上下文用量的百分比监控。70% 时给模型打"提醒"（省着点写），90% 时"撞顶"。
- **撞顶 / 换班（handoff）**：水位到 90% 不硬断——系统让当前模型写一份"交接书"然后**换一班接着干**，对话不死。交接书四件套：三分法内容（目的/已完成/未来方向）、足迹（干过什么打卡清单）、瘦身写作间（用一次便宜的小调用专门写交接书）、开工指引（下一棒第一句看到的话）。
- **棒次 / 保险丝**：换班的第几班叫"棒次"（shift），最多连续换几班有上限（handoffMaxShifts，默认 5，叫保险丝），防无限续跑。
- **话题压缩（topic compression）**：聊着聊着旧话题会被 LLM 压缩成摘要存起来（`_compressed/` 下的 markdown 压缩档），原文挪进归档（`messages_archived.jsonl`，可恢复）。这样历史无限增长也不撑爆上下文。话题边界由"规则 + LLM 裁判"判定。
- **热存储 / 归档**：热存储 = 当前活跃的消息文件；归档 = 被压缩收走的原文。聊天记录永不因压缩消失（两套都能读回）。

### 2.3 工具体系

- **内置工具**：engine 自带的 15 件工具：读文件、写文件、改文件、列目录、bash、跑命令、派子代理（两种）、取技能、联网搜索、写信两件、回忆、生图、取工具（load_tool）。其中写类操作要人工审批。
- **审批 / requiresApproval**：危险工具（写文件、跑命令等）执行前要人在界面上点确认。60 秒不点视为拒绝。
- **本会话免问**：审批时可以选"这次会话都别问了"。但**五高危工具**（write_file / edit_file / run_command / dispatch_subagent × 2）永远不允许免问——这份名单叫 NO_REMEMBER。
- **MCP（Model Context Protocol）**：外部工具协议。engine 能连 stdio MCP server，把它们的工具引进来，名字长这样：`mcp__<服务器>__<工具>`。
- **外部插件 / 器官（external plugin）**：用户自己写的纯 JS 插件，放进数据目录就能扩展系统（注册 `ext__` 前缀工具、监听引擎事件）。叫"器官"是因为 21 个内部插件被视为默认器官组。
- **动态工具**：`mcp__` 和 `ext__` 前缀的工具的合称（相对"内置工具"）。它们是 L6-ext 裁剪和按需目录的适用对象。
- **L6-ext 分流**：超预算时先砍动态工具、内置工具永不砍的规则（2026-08-26 封口）。判据就是名字前缀，读不到名字的保守归内置不砍（fail-safe）。
- **按需工具目录（tool catalog）**：动态工具默认**不**把完整定义塞进每轮请求（太烧 token），只在 L1 放一行缩略目录；模型要用时先调 `load_tool` 取回完整定义再调用。取回后本会话内自动带着（session 粘性，LRU 16 件）。
- **load_tool**：第 15 件内置工具，就是上面那个"取回"入口。
- **blurb**：目录里每个工具/技能那一行一句话简介。
- **blurb 策展**：blurb 由 LLM 首次出现时概括一次、落盘永久复用（`tool-blurbs.json`）；失败就退回机械截断且不记盘（下次再试）。
- **blurb 管理面（v3）**：blurb 变成用户可见可管的资产——设置子页面 `/settings/tools` 能看状态（待生成/LLM/已编辑/已过期）、手动重生成、直接编辑。**用户编辑的永不被自动覆盖**。
- **skill 覆盖层**：Skill 的一句话简介也能被用户编辑覆盖——但只改 L1 展示行，**SKILL.md 原文一个字不动**。

### 2.4 协作与社交

- **dispatch_subagent（派子代理）**：人形可以"借用"另一个人形帮自己干活（前台等结果 / 后台异步）。
- **swarm（蜂群）**：一份简报 × 最多 16 个傀儡批量派发，干批量分析类活。傀儡无审批通道，所以 swarm 只适合只读任务。
- **puppet 型号库**：傀儡的四种内置"工种"（规划师/码农/调研员/审查员）+ 用户自定义。
- **Intermind（人形间私信）**：人形之间写信。信箱是独立的 `intermind:<对方>` 会话，不看主聊天历史；收到信会触发对方"醒来读信"一轮。防连环惊醒有三道防线。
- **群聊（session）**：多人形会话，@谁谁说活，`@all` 广播。
- **感知回合**：被私信、被任务结果通知等"外部刺激"唤醒的一轮对话（不是你主动发消息触发的）。

### 2.5 算力层

- **provider（算力供应商）**：一家 LLM 服务（OpenAI 兼容/Anthropic 等）。配置含 API Key（加密落盘）、baseUrl、型号表。
- **apiMode 三族**：同一个 provider 可以讲三种协议方言：chat_completions（OpenAI 老协议）/ anthropic / responses（新协议）。按型号逐个指定，缺省回落。
- **fallback 降级链**：主 provider 挂了自动切备用的（可配一串）。
- **llm_calls 账**：每次 LLM 调用都记一条流水（`llm_calls.jsonl`），用量统计端点按天/模型/Agent 聚合。
- **型号表**：provider 下登记的模型清单（带 contextWindow 等元数据），水位预算从这儿查。

### 2.6 sidecar 与向量记忆

- **sidecar**：Rust 写的可选进程，专职向量索引（HNSW 算法）。gRPC 通信。
- **向量记忆 / 语义检索 / L4 注入**：把历史记忆做 embedding 存进 sidecar，聊天时按"和当前话题像不像"捞相关旧记忆注入上下文。"她记得三个月前那件事"靠的就是这个。
- **embedder**：把文本变向量的模型（OpenAI text-embedding-3-small 或 Mock）。
- **tombstone（墓碑）**：向量删除不彻底抹除，先打墓碑标记，物理清理由后台 compaction 处理。
- **收编拓扑**：sidecar 和 engine 互相知道对方——sidecar 启动时发现 engine 已在跑（看到 engine.pid 文件）就"纳管"它而不是重复拉起，互为监护。
- **自启唤醒（2026-08-26）**：以前 sidecar 只能手动 `cargo run` 启动；现在可以在设置里开 `sidecarAutoStart`（默认关），engine 启动后自动拉起它（已在跑就直接纳用）。找不到二进制只警告不炸 engine。
- **纳用短路**：自启前先探活——已有健康 sidecar 在跑就不重复拉起。

### 2.7 存储与工程纪律

- **DATA_DIR**：所有运行时数据的老巢（默认 `~/.cloudmind-zome`）。config、人形工作区、记忆、索引全在里面。
- **工作区**：每个 Agent 在 DATA_DIR 下的专属目录（`agents/<id>/`），人格文件、消息、记忆、动作日志、可写文件区都在这。
- **files/**：工作区里工具唯一可写的子目录（写操作被路径解析锁死在这）。
- **DocumentStore**：全仓统一的 JSON/JSONL 文件读写层。铁律：**tmp+rename 原子写**（先写临时文件再改名，崩溃不留半截文件）、写操作按文件路径串行排队、损坏文件隔离成 .corrupt 备份后空态启动。
- **schemaVersion**：所有落盘文件带版本戳，格式升级时旧文件惰性迁移，高版本文件绝不乱动。
- **启动对账（reconcile）**：engine 每次启动先扫一遍"上次有没有烂尾"（没压缩完的话题、没写完的状态、丢失的后台任务），能补的补上。崩溃不死数据靠它。
- **worker 退役重建**：改了一个 Agent 的配置，它的 worker 就被退役，下次用到时按新配置重建——所有"粘性状态"（如已取回工具集）随之自然清空。这是很多"配置热生效"的实现方式。
- **浮空 promise 禁令**：fire-and-forget 的异步调用必须挂 .catch——不允许静默吞错误的悬空 promise。
- **NO_REMEMBER 五高危**：见 2.3 审批条。

### 2.8 调度与自动化

- **scheduler（定时任务）**：cron 表达式定时给人形派活（持久化，重启恢复）。
- **plan（计划）**：给人形下的多步骤任务单，按行执行、可暂停/恢复/重试。
- **handoff resume loop**：撞顶换班后自动续跑的循环（600ms 延迟接力），可被用户消息打断。
- **后台任务表（subagent-tasks）**：后台子代理任务的持久化台账，重启后中断的标 lost 不自动复活。

## 三、架构骨架（无代码版）

**进程级**：你 ←→ web（Nuxt，3000 端口）←→ engine（8848 端口，REST + WebSocket）⇄ LLM 服务商；engine ⇄ sidecar（gRPC :50051，可选）。

**engine 内部**：薄组合根（bootstrap）按序挂 22 个 Cordis 插件 → 启动断言 → 启动对账 → 监听端口 → （可选）自启 sidecar。启动后的心脏是每个 Agent 一个的 worker 串行队列——同一 Agent 的事一件一件来，天然无并发冲突。

**一轮对话的内部旅程**：消息入队 → 话题边界检测（该压缩的旧话题送后台）→ 组装 L1 人格 → ContextPipeline 组装 L1–L6（超预算按 L5→L4→L6-ext→L3 降级）→ 发给 LLM（走 record 记账 + resilient 重试链）→ 模型调工具就走审批/执行/落账 → 每步落盘 → 水位监控（70% 提醒/90% 换班）→ 回合结束 → 记忆沉淀（压缩、经验、向量索引）。

**数据都在 DATA_DIR**：全局配置、人形工作区（人格/消息/记忆/索引）、MCP 配置、blurb 缓存、插件清单。删了它等于格式化整个系统的"人生"。

## 五、迷路时的读法

1. 想知道"这是个什么项目" → 本文 + README.md。
2. 想知道"某机制怎么实现的" → 架构文档.md（按子系统分节）。
3. 想知道"X 功能做了没有" → 路线图.md（已实现/部分实现/规划中/已废弃四档流水账，每条带日期）。
4. 想调接口 → API.md（端点契约）+ 引擎起起来看 `/docs`（Swagger UI，带 token）。
5. 想改代码 → 开发指南.md（目录结构、启动流程、怎么加工具/插件/页面）。
6. 想知道"最近干了什么" → docs/superpowers/ 下的 specs/ 和 plans/（每单的设计定案与实施计划，决策逐条带理由）。
