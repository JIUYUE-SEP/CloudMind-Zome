## 一、这是什么

CloudMind-Zome（仓内简称 CMZ）是一个**纯 Web 形态的"人形"系统**——你在浏览器里养若干个有名字、有人格、有记忆的 AI 角色（仓内叫 **Agent / 人形**），跟它们私聊、拉群聊、让它们互相写信、派它们干活。

它不是一个聊天框套壳。核心命题是：**让 AI 角色像"活的"一样持续存在**——有人格文件、有长期记忆、会自己管理上下文、会定时干活、会互相社交。

**产品定位**：只面向**本地运行、自己部署自己用**，不做分发形态。

**形态三分件：**

- **engine**（Node.js 引擎，核心）：跑在 `127.0.0.1:8848`，管对话循环、记忆、工具、调度、REST/WS 接口。内部 Cordis 插件化，22 个内部插件 + 外部插件体系。
- **web**（Nuxt 前端）：跑在 `localhost:3000`，聊天界面 + 全套管理面。
- **sidecar**（Rust，可选性能组件）：向量索引专用进程。不跑它系统照常，只是跨会话语义记忆静默关闭。

**一句话主循环**：你发消息 → 该人形的专属 worker 排队接单 → 组装上下文发给 LLM → LLM 边说边可能调工具 → 结果落盘、记忆归档 → 流式推回浏览器。其余 90% 的代码都在给这个循环做三件事：**省 token（上下文成本）、不丢东西（持久化与对账）、不失控（审批与降级）**。

## 二、词汇解释（按域分组，项目专属词汇）

### 2.1 人格与心智

- **Agent / 人形**：系统里的一个 AI 角色。有 id、名字、人设、模型配置、工具白名单、记忆文件。不是"一个 prompt"，是有持久状态的实体。
- **SOUL.md**：人形的人格核心文件（你是谁、性格、说话方式）。每轮对话注入 L1，**永不裁剪**。
- **MIND.md**：人形的"经验档案"——话题压缩时系统顺手沉淀的经验块（带置信度），相关时自动召回。"她自己写的读书笔记"。
- **心智（mind）**：SOUL + MIND 合称；engine 有 mind 插件专管。
- **傀儡（puppet）**：一次性分身。主人形派它干子任务：无人格无记忆、用完即弃，但用主人的模型和工具。干脏活不污染主人格。
- **delegate（借用）**：与傀儡相对的另一种子代理——直接借用另一个完整人形干活（带它自己的人格）。
- **蓝图（blueprint）**：可视化编排的线性工作流（start / llm / tool / end 四种节点）。给非人形的自动化流程用。
- **瞬态回合（ephemeral）**：蓝图等"非人形流量"的标记——不写入任何人形的记忆与话题，防人格历史被机器流量污染。
- **感知回合**：被私信、任务终态通知等外部刺激唤醒的一轮对话（不是你发消息触发的）。

### 2.2 上下文体系（全仓最厚的机制区）

- **ContextPipeline（上下文管线）**：组装每轮发给 LLM 的输入的分层流水线。分成 L1–L6 层，超预算按固定顺序降级。
- **L1**：人格层（SOUL + 安全准则 + 技能目录 + 按需工具目录）。永不降级。
- **L3**：热上下文——当前会话近期消息。降级从最旧截断。
- **L4**：语义检索结果——跨会话"相似记忆"（见 2.6）。降级保留高相关。
- **L5**：话题摘要——旧话题压缩后的摘要。降级先丢最旧。
- **L6**：工具定义。分两档：**L6-core**（15 件内置，永不裁）、**L6-ext**（动态工具，可先砍）。
- （L 层编号有缺——L2 已随清理删除，当前就是这五层。）
- **降级序列**：L5 → L4 → L6-ext → L3。人格与核心工具永远不动。
- **水位（watermark）**：上下文用量百分比监控。70% 提醒模型"省着写"，90% 撞顶。
- **W 查找链**：水位窗口（W）的取值顺序：型号表 contextWindow → Agent 显式 maxContextTokens → 缺省 80_000。
- **撞顶 / 换班（handoff）**：90% 不硬断——当前模型写"交接书"后换一班接着干，对话不死。
- **交接书四件套**：换班的产出规范——三分法内容（任务目的/已完成/未来方向）、足迹（工具打卡清单）、瘦身写作间（专门一次便宜小调用写交接书）、开工指引（下一棒第一眼看到的话）。
- **棒次 / 保险丝**：第几班 = 棒次（shift）；连续换班上限 = 保险丝（handoffMaxShifts，默认 5）。
- **chainId / 仲裁面**：换班链的代际标记与统一取消通道——双开窗口、半开重连不会造成两条链互踩。
- **话题压缩（topic compression）**：旧话题被 LLM 压成摘要存档（`_compressed/` 压缩档），原文挪归档（`messages_archived.jsonl`，可恢复）。历史无限增长也不撑爆上下文。
- **话题边界裁判（方案 C）**：什么时候算"换了话题"——规则触发优先，每攒 6 轮再由 LLM 语义判切；判 NEW_TOPIC 在判决依据消息前一刀切，切前还复核要不要拆成两段。
- **双程压缩（twoPassCompression）**：压缩先出草稿再修订一遍的两遍模式（Agent 级开关，默认关，灰度观察中）。
- **memory flush**：压缩同一次调用顺手产出"长期记忆事实"（一句话一条 + 置信度），落 memories.jsonl 并进向量索引。
- **importance 差异化保留**：话题/记忆分高/普通/低重要度——高重要的摘要常驻注入、高重要记忆不做时间衰减。

### 2.3 工具体系

- **内置工具 15 件**：read_file / list_files（读列，免审批）、write_file / edit_file / bash / run_command（写类，要审批）、dispatch_subagent / dispatch_subagent_batch（派子代理）、skill（取技能正文）、web_search（联网）、send_private_message / read_private_messages（私信）、recall（回忆归档）、generate_image（生图）、load_tool（取动态工具）。
- **审批 / requiresApproval**：危险工具执行前要人在界面点确认，60 秒不点视为拒绝。傀儡上下文没有审批通道，写类一律 fail-closed。
- **本会话免问 / NO_REMEMBER 五高危**：审批可选"本会话都别问了"；但 write_file / edit_file / run_command / dispatch_subagent × 2 五件永远不许免问。
- **MCP（Model Context Protocol）**：外部工具协议。engine 连 stdio MCP server 引入它们的工具，命名 `mcp__<server>__<tool>`。带自愈重连（封顶一次）、断线保注册（server 崩了工具不消失）、审批按只读标注 fail-closed 映射。
- **外部插件 / 器官（external plugin）**：用户自写的纯 JS 插件（DATA_DIR/plugins/ 下），可注册 `ext__` 前缀工具、监听引擎事件。全局 plugins.json + 按 Agent plugins.yml 双清单。叫"器官"是因为 21 个内部插件（加 external 加载器自身 = 22 个实挂）被视作默认器官组。
- **动态工具**：`mcp__` 与 `ext__` 前缀工具的合称（内置工具的反面）。
- **L6-ext 分流**：超预算先砍动态工具的规矩。判据 = 名字前缀；读不到名字的保守归 core 不砍（fail-safe）。
- **按需工具目录（tool catalog）**：动态工具默认**不**全量塞进请求，只在 L1 放一行缩略目录；要用先调 `load_tool` 取回完整定义。取回后本会话自动带着（session 粘性，LRU 16，取回序）。
- **load_tool**：第 15 件内置工具，目录的取回入口。免审批、原子 fail-closed。
- **取回即注入 / 对账（reconcile）**：取回的工具下一 ReAct 步就能调；每步重建工具表时和"预算裁剪结果"对账——被裁的不擅自复活，你显式再取一次才合法复活。
- **blurb**：目录里每个工具/技能那一行一句话简介。
- **blurb 策展**：blurb 由 LLM 首现一次概括、落盘 tool-blurbs.json 永久复用；失败退回机械截断且不记盘（失败=缺席，下次自动重试）。
- **blurb 管理面**：blurb 是用户可见可管的资产——`/settings/tools` 子页面看四态（待生成/LLM/已编辑/已过期）、重生成、行内编辑。**用户编辑永不被自动覆盖**。
- **skill 覆盖层**：Skill 的一句话简介也可被覆盖——只改 L1 展示行，SKILL.md 原文一字不动。
- **files/ 限制**：写类工具被路径解析锁死在 Agent 工作区的 files/ 子目录，关键状态文件（agent.json 等）在保护名单。

### 2.4 协作与社交

- **dispatch_subagent**：派子代理——前台（默认 120s 等结果）或后台（持久化任务表，可查询/续跑）。kind 分型：delegate 借用人形 / puppet 傀儡。
- **swarm（蜂群，dispatch_subagent_batch）**：一份简报 × ≤16 傀儡批量派发。burst 坡道限速 + 429 限流自适应；傀儡无审批通道，只适合只读/分析/汇总。
- **puppet 型号库**：傀儡的工种模板——内置四型号（规划师/码农/调研员/审查员）+ 自定义。
- **Resume / 通知注入**：终态子任务可按同简报续跑；任务结束时向主人注入"[系统通知]"感知回合（每人只发一次）。
- **Intermind（人形间私信）**：人形之间写信。信箱是独立的 `intermind:<对方>` 会话（不进主聊天历史，双方对称双写）；收信触发对方"醒来读信"；防连环惊醒三防线；热存储 200 条封顶溢出归档。
- **搭车（intermindRide）**：被信唤醒的那一轮里回信只入队不再唤醒对方——防 ping-pong 死循环。
- **群聊（session）**：多人形会话，@id/@name 精确路由，`@all`/`@所有人` 广播，消息 promise chain 串行防回复颠倒。

### 2.5 算力层

- **provider（算力供应商）**：一家 LLM 服务。配置含 API Key（AES-256-GCM 加密落盘）、baseUrl（SSRF 校验禁内网）、型号表。
- **apiMode 三族**：同一 provider 可讲三种协议方言——chat_completions（OpenAI 老协议，缺省）/ anthropic / responses（新协议）。可按型号逐个覆盖。
- **DSML**：DeepSeek 系模型在 chat_completions 协议下工具调用变乱码文本的毛病（仓内叫法）。现行根治法 = flash 型号走 responses 协议。
- **型号表**：provider 下登记的模型清单（带 contextWindow 等元数据），水位预算和协议选路都查它。
- **resilient 韧性层**：LLM 调用的错误分类重试（429/5xx/网络/超时指数退避；4xx 立败；流式仅首事件前可重试）+ 按 Agent fallbackProviderIds 切备用 provider。每次底层尝试独立记账。
- **llm_calls 账**：每次 LLM 调用记一条流水（模型/token/耗时/成败），`GET /compute/usage` 按日/模型/Agent 聚合用量。

### 2.6 sidecar 与向量记忆

- **sidecar**：Rust 写的可选进程，专职向量索引（HNSW，余弦距离）。gRPC 通信（Upsert/Search/DeleteDocs/DeleteAgent/Health）。
- **向量记忆 / 语义检索 / L4 注入**：历史消息做 embedding 存 sidecar，聊天时按相似度 × 时间衰减捞相关旧记忆注入上下文。"她记得三个月前那件事"靠这个。
- **embedder**：文本变向量的模型（OpenAI text-embedding-3-small 或 Mock）。
- **tombstone（墓碑）**：向量删除先打墓碑标记，物理清理由启动/运行期 compaction 处理。
- **收编拓扑**：sidecar 与 engine 互相纳管——sidecar 启动看到 engine.pid 就收编监控（不重复拉起）；engine 自启 sidecar 前先探活纳用。互为监护闭环。
- **自启唤醒**：`settings.sidecarAutoStart`（默认关）开启后 engine 启动后自动拉起 sidecar。五档二进制发现序（ZOME_SIDECAR_BIN → 仓内 release → debug → PATH → cargo run），全灭只警告不炸启动；关停两段式（SIGTERM→5s→SIGKILL / Windows taskkill）。
- **纳用短路**：自启前 200ms 探活——已有健康 sidecar 在跑就直接用，不重复拉起。手动 `cargo run` 永远是合法路径。

### 2.7 安全与隐私

- **本地鉴权**：REST 全局 Bearer token（除 /health 与 /ws/*），token 随机生成落盘 0600；WS 握手鉴权 + Origin 白名单。
- **审批审计**：审批请求/批准/拒绝/超时/免问命中等八类事件全部落盘，参数摘要脱敏。
- **隐私收敛口径**：日志与错误响应统一脱敏——SSE 帧/工具参数 raw 分档截断标注（参数类截 300、prompt 等原始文本截 500）、上游错误只落固定文案不落原文、web 侧 token 失效即清重取。
- **fail-closed / fail-safe**：本仓两条安全哲学——fail-closed = 不确定就拒绝（审批、命名空间、配置校验）；fail-safe = 不确定就保守归安全侧（工具分类读不到名字归 core 不砍）。

### 2.8 存储与工程纪律

- **DATA_DIR**：所有运行时数据的老巢（默认 `~/.cloudmind-zome`）。删了它 = 格式化整个系统的"人生"。
- **工作区**：每个 Agent 在 DATA_DIR 下的专属目录（agents/<id>/）。
- **DocumentStore**：全仓统一文件读写层。铁律：**tmp+rename 原子写**（崩溃不留半截文件）、写操作按文件路径串行、损坏文件隔离 .corrupt 备份后空态启动绝不覆盖。
- **schemaVersion**：落盘文件带版本戳，格式升级旧文件惰性迁移，高版本文件绝不乱动。
- **启动对账（reconcile）**：engine 每次启动先扫"上次有没有烂尾"（未压缩完的话题/丢失的任务/中断的换班），能补则补。崩溃不死数据靠它。
- **worker 退役重建**：改了 Agent 配置 → 它的 worker 退役，下次用到按新配置重建——所有"粘性状态"随之自然清空。配置热生效的标准实现。
- **一次性会话**：subagent_/blueprint: 前缀的会话不登记去重状态（防机器流量挤占真人会话的注入去重槽）。
- **浮空 promise 禁令**：fire-and-forget 的异步必须挂 .catch，不许静默吞错。
- **五道工序**：实现 → 亲验 → 独立 review → 修复 → 复验（验收三件套 lint/typecheck/test 打底）。本仓现行工作流。
- **双眼睛评审**：实现者与评审者用不同模型——不同模型盲点不同，漏网项靠第二双眼睛兜。
- **存在性验证先行**：评审报告先验证再修，杜绝按报告瞎修。

### 2.9 前端词汇

- **通讯中枢**：聊天主界面（私聊/群聊）。
- **行动中心**：定时任务管理页。
- **自动委托**：子代理任务管理页。
- **广播站**：更新日志页（/changelog，手工维护的内容文件）。
- **算力中枢**：provider/型号管理页。
- **审批卡片**：界面上 60 秒倒计时的确认卡（断线自动失效）。
- **用户档案 / 心智侧写**：纯前端 localStorage 的用户信息，**不写给 engine**（隐私口径）。
- **单/多模式**：hub 顶栏的呈现层切换。单模式 = 只跟一个选定人形打交道（侧栏收敛为选择器直达私聊，藏群聊与广播站入口；管理页不受影响）；多模式 = 完整界面（缺省）。状态只存 localStorage，engine 无感知；选中的人形被删会自动回退多模式并提示。

## 三、架构骨架（无代码版）

**进程级**：你 ←→ web（Nuxt，:3000）←→ engine（:8848，REST + WebSocket，全局 Bearer）⇄ LLM 服务商；engine ⇄ sidecar（gRPC :50051，可选）。

**engine 内部（启动链）**：薄组合根 bootstrap 按序挂 22 个 Cordis 插件 → 启动断言（缺服务即炸）→ engine/ready 事件（启动对账 → scheduler 起轮询）→ http.listen() → （可选）sidecar 自启 → 注册优雅关停钩。

**运行心脏**：每个 Agent 一个 worker 串行队列——同一 Agent 的事一件一件来，天然无并发冲突；配置变更经 WorkerRegistry 退役重建。

**一轮对话的内部旅程**：消息入队 → 话题边界检测（旧话题送后台压缩）→ L1 人格组装（SOUL + 技能目录 + 按需工具目录）→ ContextPipeline 组装各层（tiktoken 真实计数，超预算按 L5→L4→L6-ext→L3 降级）→ 发 LLM（记账 + 韧性重试链 + apiMode 选路）→ 模型调工具走审批/执行/审计/落账 → 每步落盘（崩溃最多丢当前步）→ 水位监控（70% 提醒 / 90% 交接书换班）→ 回合结束 → 记忆沉淀（话题压缩、经验、长期记忆、向量索引）。

**数据全在 DATA_DIR**：config.json（全局配置）、auth-token、agents/<id>/（人格、消息、压缩档、归档、长期记忆、动作日志、LLM 账、技能史、可写 files/、向量索引）、mcp-servers.json、plugins.json、tool-blurbs.json、各清单文件。

**web 页面地图**：通讯中枢（私聊/群聊）、Agent 编辑器、算力中枢、行动中心（定时任务）、自动委托（子代理）、蓝图画布、广播站（更新日志）、系统设置（含外部插件管理、系统信息、工具与技能简介子页面）、日志面板。

## 四、子系统全景（现状）

**对话**：WS 流式分帧（正文/思考/工具调用/结果）、私聊 + 群聊（@路由/广播/串行防颠倒）、输入校验。

**Agent 引擎**：ReAct 循环（水位主判据 70/90、单轮 100 步保险丝）、ContextPipeline 分层 + 降级序列、换班移交四件套 + 控制面状态机 + 自动续跑、瞬态回合隔离。
